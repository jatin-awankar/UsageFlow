# Disposable pilot evidence smoke

Run `npm run test:pilot-evidence -- --smoke` from the repository root. It requires local Docker, Node.js, npm dependencies, and free loopback ports. The runner starts fresh PostgreSQL and Redis containers, applies migrations, seeds synthetic data, then runs the real Next.js API and ledger worker. It sends three requests: original, identical retry, and changed quantity with the same idempotency key. It does not run the volume workload.

The runner removes only containers and child processes named for its random run ID. It retains `sender-journal.jsonl`, `smoke-evidence.json`, and process logs under `/tmp/usageflow-pilot-evidence/<run-id>` (override the parent with `PILOT_EVIDENCE_DIR`). The journal records and syncs each send before HTTP and each observed outcome afterward. An uncertain transport result remains in the journal. The smoke checks the journal's send/outcome sequence and records its byte length and SHA-256. Inspect the JSON Lines file and compare its byte length and SHA-256 to `smoke-evidence.json`; for example, run `shasum -a 256 /tmp/usageflow-pilot-evidence/<run-id>/sender-journal.jsonl`. Saved files contain only synthetic identifiers and response data, not the API key or database password.

For interrupted runs, run `bash scripts/test-pilot-evidence.sh --cleanup <run-id>` from the repository root, with the same `PILOT_EVIDENCE_DIR` if it was overridden. The runner retains `processes.json` with process IDs and identities; cleanup checks those identities before stopping the run's API and worker trees, then removes only the two containers named for that run. The cleanup command leaves the journal and evidence in place. Remove retained evidence only after review with `rm -r /tmp/usageflow-pilot-evidence/<run-id>`. The script does not alter deployed pilot gates or production data.
