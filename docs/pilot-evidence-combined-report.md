# Combined local pilot evidence report

Run `npm run test:pilot-evidence -- --report`. It reads every run-named directory under `PILOT_EVIDENCE_DIR` (default `/tmp/usageflow-pilot-evidence`) and writes `combined-report.json` there. `PILOT_REPORT_PATH` can select a different output file. The command reads retained artifacts only; it does not start Docker, touch a database, change a pilot gate, or delete evidence. The report is a local synthetic assessment, not a capacity or recovery guarantee.

The report lists completed, failed, and interrupted runs. Each run contains its original command where known, commit, UTC bounds, tested environment, resource samples and limits where recorded, request and persisted counts, stage latency denominators, and computed artifact hashes. `verified: true` means the artifact hash and byte count match the original evidence declaration. Older interrupted runs may have no declaration; the report records the computed hash and marks verification unavailable. Completed runs with an undeclared or mismatched journal, backup, or export-row hash fail the check. Failed and interrupted runs remain visible; their missing fields are not treated as successful measurements.

Volume is opt-in: `npm run test:pilot-evidence -- --volume`. Routine `--report` does not rerun it. The combined report evaluates each target per run against that run's configuration and sample. A small fault or restore sample cannot establish the monthly capacity targets. Export creation and pagination have separate durations. Restore has distinct pre-replay absent original IDs and quantity, post-replay remaining original-ID loss and replayed or unrecovered quantity, worker/queue recovery, ingestion RTO, and full-reconciliation RTO. Replayed quantity never counts as recovery of a missing original ID. Unset RTOs stay null with a failure or timeout status.

Review each retained run's journal, backup, logs, and report before removal. An interrupted run's owned processes and containers can be cleaned with `npm run test:pilot-evidence -- --cleanup <run-id>` using the same `PILOT_EVIDENCE_DIR`. This removes only run-named containers and registered child processes and keeps journals and backups. No production credentials or data are used, and pilot gates remain closed. A rollout decision must review the evidence separately.

A disclosed failed or incomplete run makes the combined report check fail while remaining visible in the output. The check also fails when required evidence is absent or internally contradictory, including a missing scenario in a completed fault run. Some older interrupted runs lack a completed schema and are explicitly marked incomplete; their computed hashes do not establish verification against an original declaration. Usage quantity is reconciled independently of rated money. A rated amount is checked against an independent expected amount only when that expectation was retained in the run; otherwise that monetary comparison remains unmeasured in the combined report.
