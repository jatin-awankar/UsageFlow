# Disposable PostgreSQL restore drill

Run `npm run test:pilot-evidence -- --restore` with local Docker and installed dependencies. The opt-in runner creates synthetic organization, Customer, subscription, metric, price, and API key data in fresh PostgreSQL and Redis containers. It starts the real API and worker. No deployed configuration or pilot gate is changed.

The sender syncs each send and outcome to `restore-journal.jsonl`. While ingestion continues, the runner executes `pg_dump -Fc -U postgres -d postgres` to `postgres.dump`. It records backup start, logical snapshot completion when `pg_dump` exits, and backup finish after syncing the archive. The reported backup gap is snapshot completion to outage. PostgreSQL acquires the MVCC consistency point during the dump, so the report also preserves the bounded consistency-point gap; it does not claim an exact timestamp for that internal point. Writes are not paused. A further accepted event is deliberately sent only after backup completion. The runner stops the original API and worker, starts fresh PostgreSQL and clean Redis containers, restores with `pg_restore -U postgres -d postgres --no-owner --no-privileges`, and runs the same checkout's API and worker against them. Redis jobs from the original stack are unavailable; persisted PostgreSQL intents drive worker recovery.

Before any replay, `restore-evidence.json` records disjoint survived, absent, and unresolved original-ID lists. The absent list and quantity are observed pre-replay loss. The drill replays each original journal send with its exact key and payload, recording duplicate responses and replacement IDs separately. Final raw, projected, rated, and monetary totals are compared with journal quantities and the synthetic one-dollar unit price. `remainingOriginalIdLoss` remains nonzero when replay creates a replacement event. `unrecoveredQuantity` can reach zero without implying zero original-ID loss or zero RPO.

Outage start is the earlier of fault injection and original API unavailability. The ingestion clock ends only when the restored API accepts a journaled fresh probe and PostgreSQL read-back finds its event and processing intent. The full-reconciliation clock ends after all journaled usage has its expected raw event, projection, rating, price version, currency, amount, and no unexplained unfinished record. Pre-replay and final reports include organization, Customer, metric, and UTC-month groups; the final report retains per-event rating evidence. A timeout or failure leaves the corresponding RTO unset. These local timings do not establish a production guarantee.

Evidence, logs, journal, and backup remain at `/tmp/usageflow-pilot-evidence/<run-id>` by default; `PILOT_EVIDENCE_DIR` changes the parent directory. The report stores byte lengths and SHA-256 hashes for the journal and backup. Cleanup removes only run-named containers and recorded child processes. After an interruption, run `npm run test:pilot-evidence -- --cleanup <run-id>` with the same evidence parent. Review retained evidence before deleting it manually. This drill has a small 31-event sample; the separate volume, burst, fault, and export drills supply their own measurements.
