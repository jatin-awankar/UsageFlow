# Pilot ledger export evidence

Run `npm run test:pilot-evidence -- --export` from the repository root. This is opt-in and creates fresh local PostgreSQL and Redis containers, a synthetic organization, an owner, two customers, a price version, an API server, and a worker. It sends 100,000 synthetic events through the real ingestion API and starts an owner-authenticated ledger export while ingestion is ongoing. No production endpoint or pilot gate is changed.

The command retains a run directory under `${PILOT_EVIDENCE_DIR:-/tmp/usageflow-pilot-evidence}/<run-id>`. It contains `sender-journal.jsonl`, `export-rows.jsonl`, `export-evidence.json`, `export-load-evidence.json`, and API/worker logs. A failed export instead writes `export-failure.json` with its phase, HTTP status or transport error, elapsed time, and partial page and row counts. Creation and complete pagination durations are separate. The export evidence records the accepted-ledger counts immediately before and after creation, the concurrently accepted population, API page and row counts, state counts, grouped totals, HTTP errors, and independent persisted rating checks. Events accepted during snapshot creation are identified by comparing the before and after sets; rows accepted after the snapshot boundary are not expected in the export. Processing states that changed across the bracket are counted as ambiguous, while stable states must match. Pending and failed events remain in every denominator.

The export has no price, currency, or rated amount columns. The run checks those fields using `RatedEvent` joined to `PriceVersion` after the worker drain, and records missing ratings as failures. Export rows are compared against the persisted snapshot rows, then against the accepted ledger bracket. A failed creation, failed page, timeout, missing or extra row, changed quantity/state, or changed grouped total fails the command.

Containers and managed processes are removed automatically after the run. To clean up an interrupted run, execute `npm run test:pilot-evidence -- --cleanup <run-id>`; this stops only processes recorded for that run and containers named for that run. The journal and evidence remain for review. To remove retained files after review, execute `rm -r "${PILOT_EVIDENCE_DIR:-/tmp/usageflow-pilot-evidence}/<run-id>"` with the run ID printed by the command. Do not use this cleanup command for an unrelated directory.

## Measured local run, 2026-09-29

Run `111cb596-6f1` passed the export command with 100,000 accepted and rated events, including 20,000 for the primary Customer. The owner API created a 50,065-row snapshot in 19.044 seconds while ingestion continued, then returned all rows over 501 pages in 95.682 seconds. There were no export HTTP errors or pagination timeouts. The accepted-ledger bracket contained 49,991 rows before creation and 50,519 after it: 528 were accepted across the bracket, 74 entered the snapshot, and 454 did not. The snapshot retained 13,335 pending, 1 processing, 36,729 processed, and 0 failed rows. For 1,120 rows, processing state changed across the bracket, so the independent before/after reads cannot identify their exact state at the snapshot instant; the owner API rows matched the persisted snapshot state for every row.

The snapshot grouped totals were 20,000 events and 39,999 units for the primary Customer, and 30,065 events and 60,128 units for the secondary Customer. After worker drain, all 50,065 exported event IDs had persisted ratings with the expected PriceVersion, USD currency, effective unit price, quantity, and rated amount; the rated sum was 100,127, matching the expected sum. The full 100,000-event ledger had zero missing projections, ratings, pending, processing, failed, unrated, retry, or rating-failure records at the final checkpoint. The sender made 100,017 HTTP attempts, including 11 HTTP 500 responses that were recovered with the same idempotency keys; no transport attempts remained unresolved. Its journal hash and export-row hash are in the retained reports.

On this host, only 7.685% of accepted events completed both projection and rating within 60 seconds, so the one-minute processing target failed. PostgreSQL restore, provider recovery, and any production capacity or recovery guarantee remain unmeasured. The pilot gates remain closed. The failed and interrupted synthetic runs `4c04791a-5af`, `4d5c31bc-71a`, and `5b6de9ea-ee6` are also retained. The second exposed the large Prisma export query error fixed by bounded snapshot reads; the third completed export and rating but exposed a reporter comparison that treated JSON key order as a totals mismatch. The focused grouped-total regression test covers that reporter defect.
